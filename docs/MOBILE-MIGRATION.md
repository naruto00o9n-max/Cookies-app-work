# الانتقال من Cookies Tracker إلى تطبيق Cookies

## البنية والفرق عن Railway

الهاتف يعرض الواجهات ويحتفظ بنسخة محلية للقراءة. الدخول والأوامر تذهب إلى HTTPS API عند الطلب. API تتحقق من الهوية والصلاحيات وتكتب في MongoDB الحالية. المهام المجدولة تستدعي endpoint محميًا للنسخ الاحتياطي وتذكير الدفع ومزامنة أزورا. لا حاجة لتشغيل `main.py` أو اتصال Discord gateway دائم.

هذه بنية **دون خادم تديره باستمرار**، وليست بنية «دون خدمة خلفية». MongoDB اتصالها المشترك لا يكفي لحماية صلاحيات كل عضو إن وضعت بيانات الاتصال في التطبيق. لو كان رفض أي خدمة خلفية شرطًا مطلقًا، فالمزامنة الآمنة الحالية بحساب Discord وMongoDB لا تتحقق بهذا التصميم، ويلزم تغيير متطلبات المصادقة/قاعدة البيانات.

يمكن استضافة مجلد `dashboard` كدوال Next.js على مزود يدعمها. احتفظ بقاعدة Atlas الحالية. لا يعتمد الكود على أوامر Vercel أو Railway. لا يوجد نشر أو موارد سحابية أنشئت ضمن هذه النسخة. الحدود المجانية والتكاليف تُراجع لدى المزود المختار؛ نقل التطبيق لا يلغي تكاليف البيانات والشبكة.

## إعداد المهام

`GET /api/mobile/jobs` يحتاج `Authorization: Bearer CRON_SECRET`. اختر مُجدولًا يستدعيه كل عشر دقائق. يوجد workflow جاهز في `.github/workflows/mobile-jobs.yml`؛ لا يعمل على الخدمة دون ضبط secrets `COOKIES_API_URL` و`COOKIES_CRON_SECRET`. جداول GitHub قد تتأخر أو تتوقف للمستودعات غير النشطة؛ لا تعدها ضمانًا دقيقًا للتوقيت. راجع ميزانية الدوال قبل مزامنة فريق كبير (نداءات فصول متعددة قد تطيل التنفيذ).

تُحفظ نسخة يومية في `mobile_backups` داخل نفس MongoDB، وتُحذف بعد 30 يومًا بمؤشر TTL. هذا ليس بديلًا لنسخة خارج قاعدة البيانات؛ استخدم تصدير JSON دوريًا. رسائل الدفع تُرسل قبل الموعد بيوم وعنده. الإشعارات لا تعمل قبل تسجيل أجهزة الأعضاء في Expo.

## النقل الآمن للبيانات

1. صدّر نسخة من البوت/Atlas واحتفظ بها خارج القاعدة.
2. اختبر على نسخة مستقلة من قاعدة الفريق، واضبط guild وصلاحيات المشرفين.
3. سجّل بحساب عضو وحساب مشرف من Android وiOS، وتحقق من رفض تسجيل العضو باسم غيره.
4. قارن تقرير الدفع والأسعار الخاصة والمعزولة والأرشيف مع البوت، واختبر أزورا على عمل مرتبط.
5. اختبر تسجيل عضوين بالتزامن، فقد الاتصال أثناء الحفظ، وتنبيهات الأجهزة والتوقيع والبناء.
6. أوقف كتابة البوت عند الانتقال الفعلي، ثم وجّه الأعضاء إلى التطبيق. لا تحذف البوت أو قاعدة البيانات قبل المقارنة.

API الهاتف تحفظ السجلات والأعمال والأسعار والشهور في معاملة MongoDB واحدة. تحتاج Atlas/replica set يدعم transactions. لن يُستبدل ذلك بحفظ جزئي على standalone MongoDB.

## ما تحقق في بيئة العمل

يوثّق [تقرير التحقق](VERIFICATION.md) نتائج الاختبارات. لم تتوفر متغيرات قاعدة الفريق أو OAuth أو حسابات توقيع؛ لذلك لم يُختبر دخول Discord الحقيقي أو Atlas أو أجهزة فعلية أو إرسال push أو API أزورا الحية. تم إلغاء الدخول والبيانات التجريبية من النسخة المنشورة.

صلاحيات الإدارة تحافظ على سلوك البوت: مالك السيرفر أو Administrator أو Manage Messages، بالإضافة إلى أي مالك مصرح به في إعداد الخدمة.
