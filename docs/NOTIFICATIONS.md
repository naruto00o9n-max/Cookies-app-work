# إشعارات كوكيز وملفات الأعضاء والأعمال

## سلوك التطبيق

بعد تسجيل الدخول لأول مرة على الجهاز، تظهر نافذة تشرح التنبيهات وتتيح «تفعيل الإشعارات» أو «لاحقًا». قبولها يفتح طلب نظام الهاتف عندما تكون نسخة التطبيق مرتبطة بخدمة الإرسال. السماح في إعدادات iOS وحده لا يسجل الجهاز في Expo ولا يثبت أن توقيع IPA يدعم APNs. لا يعرض التطبيق نجاحًا حتى يحصل على رمز الجهاز ويحفظه في API.

تفعيل الإشعارات على جهاز لا يستلزم بناء التطبيق عبر EAS: GitHub Actions يبني APK وIPA كما سبق. لكن استخدام خدمة Expo للإرسال يحتاج مشروع Expo حقيقيًا ومعرّفه وإعدادات Apple/Google للإرسال.

## إعداد مشروع الإرسال

1. أنشئ أو استخدم مشروعًا في Expo، وانسخ **Project ID** من إعداداته؛ قيمة UUID وليست اسم المشروع.
2. في GitHub → Settings → Secrets and variables → Actions → **Variables**، أضف `EXPO_PUBLIC_EAS_PROJECT_ID` بالقيمة الحقيقية. هذا معرّف عام، ليس سرًا.
3. أعد بناء ملفات الهاتف. `mobile/app.config.ts` يضمّن المعرف تلقائيًا في `extra.eas.projectId`.
4. لـ iOS: فعّل Push Notifications لمعرف `team.cookies.tracker` في حساب Apple Developer، واربط مفتاح APNs بمشروع Expo من إعدادات الاعتمادات، مثل `npx eas-cli credentials --platform ios`. وقّع IPA بملف provisioning يضم `aps-environment=production` وبنفس Bundle ID. شهادة أو أداة توقيع لا تدعم هذا الاستحقاق لن تتيح الإشعارات البعيدة. المشروع مضبوط على APNs production.
5. لـ Android: اربط تطبيق Firebase بالحزمة `team.cookies.tracker`، وضع محتوى `google-services.json` في Repository secret باسم `GOOGLE_SERVICES_JSON`. ارفع اعتماد FCM v1 لخدمة الإرسال في مشروع Expo. Action يكتب ملف الإعداد وقت البناء فقط، وconfig يستخدمه عند وجوده.
6. إذا فعّلت حماية Expo Push Service بالتوكن، ضع `EXPO_ACCESS_TOKEN` في Vercel Production ثم أعد النشر.

## اكتشاف الفصول وإرسالها

ضع Repository secrets في GitHub:

- `COOKIES_API_URL` = `https://cookies-app-work.vercel.app`.
- `COOKIES_CRON_SECRET` = نفس `CRON_SECRET` في Vercel.

Workflow **Cookies scheduled jobs** يستدعي API كل عشر دقائق؛ قد تتأخر مهام GitHub المجدولة. التوقيت ليس إرسالًا لحظيًا من أزورا.

المزامنة الأولى تثبت قائمة الفصول الحالية دون إرسال تنبيهات عن كل الأرشيف. بعد ذلك يُكتشف كل فصل جديد، بما في ذلك الفصول العشرية أو فصل أضيف بين فصول قديمة. يتلقى التنبيه من لديه سجل مساهمة في العمل، عبر أي شهر، ما لم يكن قد سجل الفصل بالفعل. المكافآت والخصومات ليست مساهمة في عمل. الأعمال المعزولة وغير النشطة لا ترسل تنبيهات.

مثال: «نُشر الفصل 28 من ‹اسم العمل› على أزورا. يمكنك تسجيل إنجازك الآن.» الضغط على الإشعار يفتح العمل، ومنه يمكن تسجيل الإنجاز مع الفصل المحدد. يُحفظ حدث منفصل لكل عضو وعمل وفصل لمنع تكراره في المزامنات التالية. التنبيه لا يسجل الفصل نيابة عن العضو.

تُرسل أيضًا تذكيرات المستحقات، إشعار بلوغ الحد المالي مرة لكل عضو في الشهر، وتحديثات المكافآت والخصومات. فشل الإرسال يُبقي الرسالة في قائمة الانتظار للمحاولة التالية.

## بيانات Discord وأزورا

تسجيل الدخول أصبح يطلب `guilds.members.read` إلى جانب `identify guilds`. يحتاج الأعضاء الذين لديهم جلسة قديمة إلى تسجيل الخروج والدخول مرة أخرى لمنح الإذن وتحديث بياناتهم. يستخدم التطبيق نك نيم السيرفر أولًا، ثم الاسم المعروض، ثم اسم المستخدم. صورة السيرفر، إن وُجدت، لها أولوية على صورة الحساب. تُحفظ البيانات المشتركة ليراها الفريق؛ بيانات عضو لم يسجل الدخول ولا توجد له بيانات سابقة لا يمكن اختراعها.

الأغلفة تأتي من `featuredImage` الحقيقي لأزورا، وتظهر في الأعمال والسجلات وصفحات التفاصيل ومركز أزورا. بعد النشر شغّل «مزامنة الآن» في مركز أزورا لتحديث الأغلفة والملخص وآخر فصل. عند غياب صورة أو فشل تحميلها يُستخدم رمز أو الحرف الأول، ولا تُستخدم صور وهمية.

صفحة العمل تعرض المساهمين والتخصصات والإنجازات والمستحقات والفصول المختلفة، مع فلاتر الشهور. الضغط على عضو يعرض مساهماته في العمل، ثم يمكن فتح ملفه الكامل وأعماله ومكافآته وخصوماته وملاحظات السجلات وتواريخها. تفاصيل جميع الشهور لا تعني إضافة المبالغ المعروضة إلى مستحقات الشهر الحالي.
