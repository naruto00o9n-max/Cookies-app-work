# Cookies · تطبيق الفريق

تطبيق React Native / Expo 57 لأندرويد وآيفون، بواجهات عربية، Cairo، بطاقات داكنة، لمسات ذهبية، زجاج على iOS، انتقالات native-stack ولمسات اهتزازية. ليس WebView.

## التشغيل والمعاينة

يتطلب Node 22+ وnpm:

```bash
cd mobile
npm ci
npm start
```

التطبيق يستخدم بيانات الفريق الحقيقية فقط. لا يوجد دخول تجريبي أو بيانات فريق وهمية. الهواتف تحتاج development build أو نسخة APK/IPA مُجهزة؛ دخول Discord بالـ custom scheme يحتاج تطبيقًا مثبتًا.

## ربط الفريق الحالي

1. اضبط متغيرات `dashboard/.env.example` في خدمة الدوال التي تختارها. `MONGODB_URI` و`MONGODB_DB_NAME` يجب أن يشيرا إلى قاعدة البوت نفسها، لا قاعدة فارغة. رابط MongoDB وسر Discord وسر الجلسة لا يدخلون تطبيق الهاتف.
2. في Discord Developer Portal، أضف OAuth redirect: `https://API-HOST/api/auth/discord/callback`. التطبيق يستخدم `identify guilds` للتحقق من العضوية وصلاحيات الإدارة؛ لا يحتاج تشغيل البوت أو `DISCORD_BOT_TOKEN`.
3. انسخ `mobile/.env.example` إلى `.env` واضبط `EXPO_PUBLIC_API_URL` على عنوان الخدمة. أعد تشغيل Expo بعد تغييره.
4. دخول الهاتف يفتح متصفح النظام، ويعود إلى `cookiestracker://auth`. رمز العودة أحادي الاستخدام، صالح لدقيقة، ومربوط بتحدي SHA-256. الجلسة تُحفظ في SecureStore لمدة أسبوع. اختبر الدخول في development build؛ custom scheme غير مملوك للتطبيق داخل Expo Go.
5. دخول Discord عبر الويب غير منفّذ؛ استخدم نسخة الهاتف المثبتة.

يمكن تشغيل API محليًا بـ `cd dashboard && npm ci && npm run dev`. الهاتف يحتاج عنوان LAN للحاسوب أو HTTPS قابلًا للوصول، وليس `localhost` الهاتف.

## بناء نسخ قابلة للتثبيت

```bash
npx eas-cli login
npx eas-cli init
npx eas-cli build --platform android --profile preview
npx eas-cli build --platform ios --profile production
```

Android preview ينتج APK. iOS يحتاج توقيع Apple Developer وتوزيع TestFlight/App Store أو توزيع داخلي مع أجهزة مسجلة؛ ملف التطبيق وحده لا يمكن تثبيته على كل أجهزة آيفون. ملفات البناء لا تُنشأ دون حسابات التوقيع. راجع حدود وأسعار EAS وApple الحالية قبل الاعتماد على مجانية الخدمة.

مشروع EAS يضيف `extra.eas.projectId` إلى إعداد Expo. الإشعارات تحتاج هذا الربط وdevelopment/production build على جهاز فعلي؛ من «مساحتي» اختر «تفعيل إشعارات الفريق». عند الخروج يُلغى رمز إشعارات الجهاز إن كان مسجلًا في الجلسة الحالية.

## البيانات والاتصال

التطبيق لا يشغّل البوت. قاعدة MongoDB الحالية تبقى مصدر الحقيقة. API تُشغَّل عند الطلب ويمكن استضافتها كدوال، فلا يلزم خادم Railway دائم. MongoDB وخدمة الدوال والمُجدول خدمات إنترنت ذات حدود استعمال؛ لا توجد هنا ضمانة «مجاني إلى الأبد».

عند انقطاع الإنترنت تُعرض آخر نسخة محفوظة. الحفظ المشترك يتوقف حتى عودة الاتصال؛ لا تُرسل عمليات مالية تلقائيًا عند العودة، لتجنب تكرارها. يُحدّث التطبيق البيانات كل 30 ثانية أثناء فتحه، عند العودة إليه، وعقب الحفظ. هذا تحديث دوري وليس بثًا لحظيًا عبر WebSocket.

لا توقف البوت قبل تجربة الفريق. خذ نسخة احتياطية أولًا. بعد بدء نقل الكتابة إلى التطبيق أوقف كتابة البوت، لأن البوت القديم يحفظ وثيقة السجلات كلها ولا يعرف معاملات التطبيق. يمكن أن يستبدل تسجيلًا حديثًا إن كتب الطرفان معًا.

## الاختبارات

```bash
npm run typecheck
npm test
npm run export
```

`npm run export` يجمع JavaScript لأندرويد وآيفون والويب؛ لا ينتج APK/IPA ولا يثبت نجاح تشغيل native modules على هاتف. اختبارات الحسابات تستخدم بيانات معزولة داخل `tests/fixtures.ts` فقط، لا تُستورد في التطبيق. فحوص المتصفح وAPI تفحص منع الدخول التجريبي وعدم كشف البيانات دون مصادقة، دون تغيير بيانات الفريق.
